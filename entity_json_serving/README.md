# Entity JSON Serving

HTTP serving module for serialized entity JSON files generated by
[headless_entity_serializer](../headless_entity_serializer).

## Requirements

- Drupal 11.4+
- [headless_entity_serializer](../headless_entity_serializer) module

## Routes

All routes require the `access entity json` permission.

### `GET /json/{entity_type}/{entity_id}/{langcode}`

Serves a single entity translation JSON file.

```
GET /json/node/1/en
GET /json/node/4523/es
```

Cache: `public, max-age=3600`

Supports ETag and Last-Modified conditional headers. Returns `304 Not Modified`
when the client sends a matching `If-None-Match` or `If-Modified-Since`.

### `GET /json/path/{alias}`

Resolves a path alias to its entity and serves the JSON file.

The translation language is determined by Drupal's language negotiation
(`LanguageManager::getCurrentLanguage(TYPE_INTERFACE)`). If the entity has
a matching translation it is served; otherwise the entity's default language
is used.

```
GET /json/path/about-us
GET /json/path/hola-mundo/3
```

#### Multi-segment aliases

Aliases containing `/` (e.g. `hola-mundo/3`) are supported via the
`AliasPathProcessor` inbound path processor. It URL-encodes slashes before
Drupal route matching so that multi-segment aliases fit in a single route
parameter. The controller decodes them back before resolution.

## Permissions

| Permission | Description |
|------------|-------------|
| `access entity json` | Access all JSON entity serving routes |

## Services

### `entity_json_serving.alias_resolver`

Resolves a path alias to `{entity_type, entity_id}` using Drupal's
`path_alias.manager`:

```php
$resolver->resolve('about-us');
```

### `entity_json_serving.path_processor`

Inbound path processor (`path_processor_inbound` tag). Encodes `/` to `%2F`
in `/json/path/{alias}` URLs so multi-segment aliases match the 3-segment
route.

## Integration

The module depends on `FileStorageManager::getEntityFilePath()` from the base
module to locate serialized JSON files on disk. Entity JSON files must exist
(regenerated via `drush hes-full` or `drush hes-incremental`).
